
# Clone Spec — Stage 2 of Clone Factory

teardown.md を、Claude Codeが自律実装できる粒度のスペックに変換する。

**最初に必ず `references/spec-format.md` を読むこと。** 出力はこのフォーマットに厳密に従う。

## 入力

- `pipeline/<product-slug>/teardown.md`(必須)
- ユーザーの追加指示(スコープ調整など、任意)

## 実行手順

### 1. teardownの検証

- Open Questions(`[要確認]`)のうち、スペックに影響するものを列挙
- ユーザー判断が必要なものは**スペック生成前に**確認する。ただし質問は1回にまとめる
- 影響が軽微なものは合理的なデフォルトを置き、スペック内に `[ASSUMED: 理由]` と明記

### 2. スコープ確定

- teardownセクション9(MVP Scope Proposal)を起点に、MVPに含める SCR-ID を確定
- 2週間で実装可能な規模に収める。目安: 画面8〜15、P0のE2Eケース10〜20
- 落とした画面・機能は必ず `out_of_scope` に記録(黙って消さない)

### 3. スペック生成(spec-format.md準拠)

生成順序を守る(依存関係があるため):

1. `02-schema.md` — データモデルが全ての土台
2. `01-screens/` — 1画面1ファイル。teardownの画面インベントリのIDを引き継ぐ
3. `03-api.md` — 画面仕様から必要APIを逆算
4. `04-e2e-cases.md` — **実装のゴール定義。ここが最も重要**
5. `05-ai-features.md` — teardownセクション7から採用分を仕様化
6. `00-prd.md` — 最後に全体を要約

### 4. 自己検証(生成後に必ず実施)

- [ ] 全SCR-IDについて: 画面ファイルが存在し、routeが一意
- [ ] 全画面の全Interactionについて: 対応するAPIが03-api.mdに存在
- [ ] 全APIについて: 使用するSchemaモデルが02-schema.mdに存在
- [ ] P0のE2Eケースだけで「ユーザー登録→コア価値の体験→課金導線」が一筆書きできる
- [ ] AIF全件にe2e_refが付いている
- 不整合があれば修正してから完了報告する

## 品質基準

- 画面仕様は「これだけ読めば実装できる」レベル。「いい感じに」等の曖昧語禁止
- E2EケースはUI操作レベルで書く(「POSTする」ではなく「保存ボタンを押す」)
- AIネイティブ機能は必ずfallback(AI失敗時のUX)を定義する

## 完了時

生成ファイル一覧、MVPスコープ(画面数・E2E P0件数)、`[ASSUMED]` の一覧を報告し、
「clone-buildに進んでいいか」を確認する。
